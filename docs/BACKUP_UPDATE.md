# Weekly public-backup update contract

The user authorizes recurring updates to `https://github.com/JasonGu1988/OpenClaw_Personal_Assistant`. The local checkout path is supplied by the runtime job, not stored publicly. This file describes the allowed procedure, not a credential or a private user-context export.

1. Verify the checkout's exact origin and clean state. Fetch and fast-forward only. Never force-push, reset, or overwrite unrelated work.
2. Inspect the current runtime locally. Construct updates from explicit harmless selections; never copy/redact the entire runtime. Refresh approved reusable code, non-secret configuration, actual software-agent definitions/roles, sanitized operational context, and sanitized scheduled-job templates.
3. Never export personal profiles, credentials, private memories, conversations, investment datasets, account IDs, private URLs, host-specific paths, access lists, bindings, execution history, logs, attachments, or runtime archives. Do not access investment-data directories. Read private role/context files only to understand reusable behavior, and author a safe summary rather than copying them.
4. Inspect scheduler state through the authorized inventory interface. Preserve original cadence, timezone, agent role, and generic intent in public templates; remove private destinations, account/session IDs, private task data, host paths, and runtime state. If visibility is restricted, document the limitation and preserve previously verified sanitized definitions rather than claiming missing jobs were deleted. Do not invent current schedules from old memory. Never alter live jobs to generate this backup.
5. Review every candidate diff for personal identifiers, secrets, and financial records. Generalize owner-specific source prompts. Privately compare content against known local sensitive identifiers/secrets without printing or recording their values. Only the explicitly requested public repository URL is an allowed owner-related URL.
6. Run the strict allowlist guard, relevant synthetic tests, and configuration patch dry-runs. Do not contact live mailboxes or send messages for testing. Run Gitleaks with `--redact` on working files and all Git history. If necessary, obtain an official scanner in a private temporary directory and verify its published checksum. If any required privacy/secret check is unavailable or fails, do not push.
7. Regenerate and verify `MANIFEST.sha256` for approved tracked artifacts, excluding itself, Git internals, environments, bytecode, and private state. Stage only reviewed allowlisted paths; inspect the staged diff and whitespace. Use generic author/committer `OpenClaw Backup <backup@example.invalid>` with per-command Git settings, not global configuration changes.
8. If no sanitized changes exist, do not create an empty commit. Otherwise commit, rescan the full history, and push `main` without force using existing local authentication. If HTTPS requires the existing GitHub CLI credential helper, use `git -c credential.helper= -c 'credential.helper=!gh auth git-credential' push origin main`; never print credentials.
9. Verify the remote branch ref equals the reviewed local commit, and remote paths/blob hashes match local artifacts. Report updated, unchanged, or blocked without private data.

The privacy exclusions remain binding even when agents, context, and jobs are included. Sanitized operational context is not permission to publish raw conversations or private memories.
